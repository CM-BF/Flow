## Bounds and failures

Retire fresh free-space gate is 32 MiB under the explicit **resource-recovery-only** exception. New durable evidence is capped at 10 MiB including compressed manifest, intent, journal, result, marker/compact outer metadata and at most 1 MiB outer raw. Space for after-action and final result is reserved before the next unlink. Product test/PG/Chrome gates remain unchanged. Restore instead requires 1 GiB + the entire selected set's logical bytes + 12 MiB before copying. Inodes/ctime are not restored; no full timestamp preservation claim is made.

The fixed file-ID order uses batches of 16 (maximum 32). Each batch observes actual available bytes and stops retirement once free >= 1 GiB + 160 MiB (1,241,513,984 B). One ACL read covers the batch's target/CAS paths; stat/ctime/content/xattrs are tied to that observation. Each target and CAS is freshly SHA-512 checked before unlink. All preserved layout and package indexes are checked first. Parent directory traversal uses NOFOLLOW and recorded identities. POSIX unlink is not an atomic compare-and-delete, so the cooperative owner freeze is essential; this is not protection against a concurrent same-UID adversary.

A durable after-action event is needed before a file enters `completedFileIds`. Failure during unlink, directory fsync, or after-action checkpoint leaves the pending ID explicitly unknown; the exact known prefix and pending intent stay readable. No recursive deletion, automatic rollback, blind retry, or claim of an empty tree. The action's first failure and outer supervision failure are separate; a child exit/timeout must not replace the earlier journal reason. The marker/resources remain on all failures. If even the final result cannot persist, the before/after journal remains the authority and the outcome stays partial unknown.

Restore creates an exclusive same-directory temporary file, runs only `/bin/cp -p` from the fixed CAS path, verifies content/mode/uid/gid/flags/xattrs/no-ACL, fsyncs, and publishes with atomic no-overwrite hard-link creation. This command does not turn the view back into RUNTIME_READY. Full restored-layout/input verification and fresh runtime admission remain separate.
