## CAS and accounting ownership

Journal is the one durable coordinator, not a second command authority. Compound slot keys contain namespace plus domain+target+lane; never ambiguous concatenated IDs and never viewId alone for existing-conversation exclusivity. Examples: (conversationId,turn), (conversationId,enqueue), (conversationId,control) shared by pause/resume, (itemId,cancel), (taskId,cancel), (taskId,steer). New creation initially uses stable viewKey; its conversation/turn slot is atomically acquired at CREATE binding. Unknown admission records retain occupancy. A validated accepted command can release its mutation lane while its receipt remains charged/retained; a steering command status unknown is delivery metadata and is not identical to an unconfirmed POST. Known rejected records may release the lane but their materials remain until an explicit eligible dismissal. Same receipt explicit retry keeps immutable key/body; competing tabs cannot overwrite it with a new record. A live view/draft record is separate from these command slots.

One readwrite transaction reads expected recordVersion, slot owner/generation and manifest generation, checks global accounting, then writes record+slots+index+manifest. Monotonic safe-integer generation exhaustion fails closed rather than wraps. Slot owner recordId plus generation prevents stale delete/recreate ABA; no unbounded tombstone list. Hashing/network occur outside the transaction. Both prepare and dispatching, CREATE binding, ACK and explicit confirmed dismissal wait for transaction complete with strict durability hint. No HTTP on failed initial CAS/commit; no automatic POST on hydration. An ACK checkpoint failure cannot revoke a network side effect already observed.

Charge formula:
actual namespace rows + actual global manifest + sum(command initial record bytes + initial slot/index bytes +32768 reservation) + sum(full draft record+its slot/index bytes).
Do not double-charge current ACK bytes on top of the reserve; do not release unused reserve early. Replacement growth includes record, new CREATE binding slot and attributable index changes and must stay within the charged unit; shared manifest/namespace counter changes are checked in the same transaction. Counters are not a second quota authority: on opening corrupt/inconsistent accounting, stop mutation and preserve records, do not silently repair by dropping unknowns.

Initial command unit candidate<=131072B for complete record+its initial slot/index; global namespace/manifest charged separately once. The test also pessimistically assigned the entire4096B-address namespace+manifest to one command to show headroom. Growth reserve32768B is charged upfront. Global cap4194304B, draft<=32, logicalcommands<=128 are simultaneous upper constraints, not promised occupancies. Full-size command units cost163840B; at most25 fit before other state.128 reserves alone exhaust4MiB. Full32x128KiB drafts also leave no room for indexes. Global-full UI must not reveal other principals' counts, names or content. Never evict unknown/rejected-undismissed material silently.

## Remaining implementation checks

Keep128KiB+32KiB as plausible capacity candidates, not delivered guarantees. Final record parser/serializer must prove the full supported envelope and all states, literal omission/null semantics, valid mixed materials, alias/slot changes and every bounded ACK projection. If a legal complete envelope exceeds the final cap, raise the per-record cap and accept fewer records; never truncate text/ref/name/key. Arbitrary unsent textarea has no public request cap: over-budget draft remains fully in memory with explicit not-durably-saved state.
