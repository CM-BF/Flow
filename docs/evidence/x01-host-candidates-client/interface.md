# Host candidate client Interface

`FlowClient.pluginHostCandidates(registrationId, { materialInstallOperationId, cursor? }, signal?)` reads exactly one advisory page with the existing owner token/cookie transport. Web consumers use this method, not new fetch. IDs and strict finite query validate before transport; the parsed body is detached before await. The fixed server contract is 7672090bed43f28f88f16bcbd0d0cfa04a0667ac (server independent review initially pending), copied byte-for-byte into the owned evidence snapshot and supplied by focused TypeScript rootDirs / exact Vite resolver, not a contracts product edit.

The response must match registration/material IDs and the exact schema. Candidate IDs are unique and strictly ordered; duplicate names are valid labels. `selectable` agrees with compatible / maintenance / material-store-mismatch / harness-unsupported. `online`, `loaded`, `callable` remain unknown, and no candidate reserves or authorizes enable. Current revision/version are response facts; do not infer a prior unknown write from them.

Cursor is opaque (finite <=512 URL-safe characters). Never decode server-private cursor JSON. Returned nextCursor must differ from the request cursor. Empty candidates with a non-null cursor are valid after raw-page policy filtering; only null ends pagination. No automatic loop, cache, prefetch, or stale-cursor reset. Server rejects cursor reuse across registration/material/revision with typed409; callers retain their selection and explicitly restart if appropriate. Web should discard a late page when its own selected registration/material or request generation changed; this slice adds no UI/cache owner.

The existing pluginAcknowledgement GET path uses the sole request transport, 15s bounded-request timeout, success65536/error4096 decoded UTF-8 byte budget before decode/parse, and stream cancel/release. Non-2xx typed center refusal preserves FlowApiError; malformed shape/identity/JSON, over-limit proxy/success or transport/abort use the existing UnknownPluginAcknowledgementError read form (no inferred state). Request schema errors remain caller usage errors. This is a representation receive policy, not TCP/heap/single-chunk or universal JSON-whitespace acceptance. Server compact responses are separately schema and route capped at65536; arbitrary proxy bytes may be rejected.

`plugin runtime-hosts PLUGIN MATERIAL_INSTALL_OPERATION [--after CURSOR]` reuses runCli / parseArgs / FlowClient / JSON output. Four positional words required; --limit and --before explicitly rejected, no arbitrary page size. Global url/json/auth behavior stays as before. Bad reads exit4 with no stdout; typed409 exit3; input/CLI misuse exit2. No command key, write, implicit runner registration, or policy/private credential lookup. Empty page still prints nextCursor.

Validation is real client + real runCli with injected Fetch. It does not prove real server authentication, PG policy/row ordering, Web display, online hosts, or provider execution. Backend remains responsible for current policy and enable recheck. Main intake must include the fixed backend contract first or in the same controlled batch; do not overwrite newer main ACK/runner/READBOUND code when applying this delta.
