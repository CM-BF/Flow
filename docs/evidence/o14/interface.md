# O14 Interface v1 — source-only draft, 0 provider

Module goal-progression owns a finite immutable owner manifest and once-only execution links. POST /api/goals/:id/progressions takes GoalProgressionAuthorization plus stable Idempotency-Key, returns { progression, replayed }; GET /api/goals/:id/progressions/:progressionId returns a <=20-node light snapshot; POST .../revoke takes { reason } plus stable key and returns { progression, replayed }. Missing/invalid key uses existing command errors. Same key/body recovers original accepted receipt; changed body conflicts. GET never creates controls or reads artifact bodies. Routes require existing owner hook.

DTO is packages/contracts/src/goal-progression.ts. Immutable manifest freezes graph revision, node/version/input/predecessor/profile references, external accepted artifact bindings, maxAdmissions<=node count, absolute expiry (creation accepts at most24h), reason and literal intermediate policy. It never infers actual input from graph titles. One unfinished/unrevoked authorization per goal; each selected node can link one execution. Revoke only stops new admissions and never cancels/claims termination of current work. Failed/uncertain/waiting/cancel-requested work stops new admissions with cause; no implicit retries or new request keys.

Production integration ports: migrateGoalProgressions(pool), registerGoalProgressionRoutes(app,pool), scanGoalProgressions(pool,boss,limit=20). Call migration030 after existing goal/context/profile schema, before serving/scanning. Reuse the existing queue scan lifecycle; call one awaited bounded sweep, await it on shutdown; module creates no timer. Candidate rotation commits before waiting on project; advancement locks project then grant then existing task paths, never project→runner. Admission uses executeGoalNode/acceptTask and PgBoss wake in the same transaction as the unique link. Profile lookup enforces configured-readonly/ordinary and live claim fencing remains authoritative.

provenance.ts loads bounded exact execution links and their fixed producer references. goals/state owns the one validity recursion; goal-delivery metadata uses it too. Within the same explicit grant, a predecessor succeeded+passed with exact latest artifact may be used operationally, while accepted_binding stays null. No arbitrary qualified JSON or public authorization bypass. Failure/unknown/input/knowledge/dependency drift invalidates reuse. Revoke/expiry stops admission without erasing historical provenance. Completion means authorized executions finished awaiting owner acceptance, never semantic goal acceptance.

Resources: <=20 selected nodes, <=64KiB authorization JSON, one admission per grant per scan, no body reads for snapshots, no native/provider calls in validation. Existing actual-input/dependency prompt bound remains16,000 chars without truncation. Pure code and records <=20MB; real PG only in Lead-agreed resource window. Shared client/exports/server mount excluded. Current fixture or injected query evidence will not be labeled model planning success.
