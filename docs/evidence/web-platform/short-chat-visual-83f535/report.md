## Concrete acceptance for the existing TODO

- For the fixed completed short reply, the transcript and composer dominate at 1280px in one pane and two panes. Use one compact, named **turn details** affordance for routine execution detail/actions, with an understandable keyboard label and focus return. The exact visual label is an implementation choice. Retain message-copy as a direct utility if already expected; do not make every action a permanent text row. Action identities, task/turn context, capabilities and plugin contributions remain intact.
- Keep queue as its own conversation-level action. A light entry is valid only when a successfully loaded, current snapshot has no waiting items, no next cursor, no paused/blocked/error/unknown receipt and no relevant action-disabled condition. Never equate not loaded, stale, disconnected or partially loaded with empty. Move technical loaded counts into details; if a compact count is shown it must state it is loaded/partial when a cursor remains. No inferred total.
- Waiting work, active execution with an available cancellation/decision action, pauses, authorization or connection loss, rejected/unknown durable receipts, stale data, reply unavailable and action errors remain visible and actionable without opening an unrelated menu. Unknown retries use their original identity and never silently send a fresh draft. Running is not automatically an error, but its stop/decision access cannot disappear.
- The normal-state grouping cannot bypass the plugin registry or directly call a hidden action. A plugin-disabled or unauthorized control must follow existing host semantics. The single entry may contain registered controls, but must not flatten per-message commands together with conversation queue commands into the wrong context. Exact host seam is subject to the separate fixed-source peer note.
- Before explicit activity expansion: no newly introduced activity list/body/detail request. Merely opening the general action menu must not incidentally load tool/thinking bodies. Before individual body expansion: zero body requests for those references. Existing compact task/turn metadata is sufficient for truthful generic details availability, not for an assertion of empty activity.
- Preserve the actual requested/effective profile distinction and current capability restrictions. Do not invent model names, totals, verification or integration facts to make the short view appear complete. Fixture/simulated provenance remains available and honest; never replace it with a production claim.
