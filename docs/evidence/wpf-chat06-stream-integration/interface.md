# App stream host boundary

Base: `6426b44cd32d10216141af13ecfa83b8879025fb`. Reuses the approved S01 module and the existing single official assistant-ui runtime. Public protocol, S01 source, conversation projection/outbox, queue, profile modules and official Thread are unchanged.

`ConversationStreamHost(viewId, projection, authority, connectionBudget)` subscribes to immutable conversation turn facts. It creates an entry only for the current active/pending turn; already observed entries can receive final settlement. Loaded completed history never initiates stream reads. A finite dirty set handles actual input changes, reconnect/visibility restoration and explicit Retry. Once drained it becomes silent. There is no new interval, SSE or fetch implementation.

Each view retains at most four turn entries and 2 MiB of UTF-8 draft text; one connection at most eight entries and 4 MiB. These limits describe draft text, not total JS heap or canonical conversation history. Two connection leases permit at most two concurrent stream requests. Inactive least-recent entries are evicted using a shared connection clock; the victim immediately republishes canonical fallback and drops draft membership/state references. Local historical drafts may disappear; canonical history remains. Three consecutive host read failures stop automatic attempts until explicit Retry or explicit plugin reactivation.

The App owns the FlowClient. `StreamAuthority` offers only bound metadata/patch readers, lifetime signal and permission subscription. The App validates connection/view/conversation/turn/task and the actual user-message anchor before reads. `flow.assistant-stream` declares `task.assistant-stream.read`; P01 `checkView` and resource authorization are both required. The activity extension is independent. Draft action membership derives only from validated S01 snapshots; opaque message or stream IDs are never parsed to authorize a resource.

Hidden/offline panes initiate no reads; pending requests are aborted and late results ignored. Close and connection replacement dispose the old lifetime. Re-enabling the extension creates an authorized read cycle; disabling clears draft data and restores canonical fallback. Each visible split pane has an independent host. The official runtime consumes the public `messageRepository` representation, with per-message WeakMap conversion via `ExportedMessageRepository.fromArray`; absent draft IDs are deleted from its repository rather than accumulated as branches. It keeps the same runtime/composer. Message conversion uses S01 output even with no patches so a typed final is explicitly complete/unknown while task/global running remains true.

GET conversation opts into `X-Flow-Assistant-Stream: patch-v1`; CREATE has no header and its stable false capability receipt is preserved. Missing/false capability means zero stream reads. Metadata/patches are lightweight bounded reads; this host does not prefetch full blocks or reply details. Only already-loaded canonical reply detail content is supplied for final settlement. Final replacement requires S01’s complete partition and matching canonical evidence; unavailable correlation retains drafts. Draft interrupted/paused/truncated/block-complete labels are visible and never claim task or verification success.

Connection help is static: blank URL means this deployment’s same-origin `/api` proxy, remote URLs come from the administrator; the documented personal-preview status command reports a private credentials-file path. No secret is read or copied by this feature.
