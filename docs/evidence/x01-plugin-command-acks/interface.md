Existing runCli plugin change already catches UnknownPluginAcknowledgementError→exit4, so CLI production is unchanged. New internal decodePluginRegistryChanged reuses decodePluginMutation envelope with runtime enable/disable. No second transport, server API, command store or retry authority.

The client parses/detaches before its first await and sends that exact serialized input. ACK validates registration/operation kind, before expected and after expected+1, snapshot/installation revision, complete version/scope/config/grants/status/time shape. Configure requires exact key/value/types plus version-declared boolean/integer range/enum/required rules and ready status. Set-grants requires exact sent array (server stores its order) and declared subset; existing configuration may be incomplete, but every present value must match its declared field and status must reflect required-field presence. Historical replay=true is checked against the original expected revision/body; there is no automatic current GET or retry. Without a trusted pre-edit snapshot the request does not carry prior version/scope or untouched fields, so no additional pre-state equality is claimed.
