# CHAT09 frozen Interface

Configuration extends the existing strict profile schema with optional `activeSteering: { protocol: "flow.active-steering.v1" }`. Omission means unsupported and preserves all legacy canonical JSON bytes/digests. Manifest `activeSteering` accepts only boolean; false/omission emits no profile field. True is allowed only for ordinary `none`/`configured-readonly` profiles, and participates in the immutable configDigest. Changing it requires a new runner identity. It is a configured host declaration, not provider availability/effective attestation.

`GET /api/execution-profiles`: one exact `X-Flow-Execution-Profile: steering-v1` header allows old and new profiles. Missing, unknown, comma-combined or duplicate headers yield only legacy-compatible profiles. Filtering occurs in SQL before limit+1, with the existing after/nextCursor UUID ordering. Every page must repeat negotiation; response uses Cache-Control:no-store. Header is format negotiation only; owner authentication is unchanged. Runner profile publication returns its entire immutable configuration without negotiation. Existing public controls.steer and conversation capability remain false.

Client change owned by F01: add an optional selection flag/value to executionProfiles options that emits this exact header on every page; no silent fallback or retry. Runner publication never strips unsupported fields to placate an older center.

The legacy adapter-only loader rejects an enabled steering manifest instead of dropping its runtime option. Startup returns one parsed activeSteering boolean with its profile; the same value configures runRunner. The existing profile guard checks the pinned profile/digest and presence of the steering port before invoking the adapter. Unpinned legacy work gets no steering port. Owner task-bound steering admission requires the currently locked task pin to identify this attempt runner's immutable, recognized steering profile; checks precede idempotency replay. Refusal writes no command/control row. Existing CHAT08 receipts/results/conditional-final protocol is unchanged.

No new migration, conversation mode, SDK loop, runtime port, provider query or Web affordance is added. Shared production factory remains separately owned by F01. Actual optional SDK UUID/queued fields remain unverified; CHAT08 treats absent evidence conservatively.
